# 数字员工聊天提及设计

English | [中文](2026-08-29-digital-employee-chat-mentions-design.zh.md)

## 目标

用户在聊天输入框中选择一个已激活的数字员工，并发送任务内容。系统为该员工创建新的根会话，将任务内容作为首条用户消息提交，然后切换到该会话。数字员工管理页继续负责实例生命周期、配置、权限和审计，不承担任务正文输入。

## 用户交互

空白聊天输入框接受位于首个语义位置的 `@`。输入后，弹出数字员工选择器，展示员工名称、模板名称和当前状态。用户选择可用员工后，输入框插入不可歧义的结构化提及，并允许继续输入任务正文。

```text
┌────────────────────────────────────────────────────────────┐
│ @运营协调员  检查本周发布计划并列出风险                   │
└────────────────────────────────────────────────────────────┘
                         发送
                           │
                           ▼
          创建员工根会话 + 提交首条用户消息
                           │
                           ▼
                切换到新建的员工会话
```

首版每次只允许选择一个数字员工。提及必须位于任务正文之前，不支持在普通会话消息中间添加员工，也不把一条消息同时发送给多个员工。已停用、正在删除或模板不可用的员工不能被选择；选择器显示不可用原因。

当用户从数字员工管理页点击“开始聊天”时，Web 应打开聊天界面并预选该员工，之后使用同一提交链路。管理页不再通过“运行任务”创建没有首条消息的空会话。

## 输入模型

数字员工提及复用现有输入引用机制的结构化 occurrence，而不是在 Host 端解析显示文本。引用至少包含稳定的员工实例 ID；员工名称仅用于展示。编辑、撤销、重做、复制粘贴和失效检查遵循现有引用生命周期。

数字员工引用与发送给模型的普通内联引用不同。提交时它充当会话路由指令，并从首条用户消息正文中移除。普通输入仍沿用现有引用序列化和消息提交行为。

输入组件只在没有既定员工所有者的空白会话入口提供数字员工选择。进入员工会话后，后续消息直接发送给该会话，不要求重复提及，也不允许通过新提及改变会话所有者。

## 原子启动

客户端向 Host 提交一个包含员工实例 ID、新 Session ID、首条消息内容和附件引用的启动请求。Host 在同一受控操作中：

1. 检查员工存在、处于激活状态且模板版本可用。
2. 根据员工实例解析身份、个性、Skills、Tools、MCP、专家和权限组合。
3. 创建由该员工拥有的根 Agent 与 Session。
4. 通过标准用户消息入口提交首条任务内容。
5. 返回已发布的 Session ID，供客户端选择并导航。

Host 是有效性和权限的最终执行者。选择器中的状态只能改善交互，不能替代 Host 校验。

任务正文为空时不提交。若首条消息包含图片或其他已有附件，启动请求使用现有附件序列化和所有权规则，不创建第二套上传协议。

## 一致性与失败

启动请求必须避免向用户暴露永久空会话。若员工解析或 Agent 创建失败，Host 不接受首条消息，客户端保留草稿、提及和附件并显示错误。

若 Agent 已创建但首条消息未被接受，Host 终止并清理本次尚未发布为可用任务的 Agent/Session，或者以等价事务机制确保它不会出现在会话列表。具体机制由拥有 Agent 创建与消息接收生命周期的 Host 服务决定。

客户端仅在 Host 返回成功后清空当前草稿并切换会话。重复点击、键盘重复提交和迟到响应沿用输入 facade 的提交尝试与 AbortSignal 规则，且同一启动尝试最多产生一个根会话。

员工在选择后、提交前被停用或删除时，Host 拒绝启动。客户端保留用户输入并将提及标记为失效，用户可以重新选择员工后再次提交。

## 身份、日志与恢复

员工所有权不能仅存在于 UI token 或显示名称中。新根 Session 的必需事件记录稳定的员工实例 ID、模板 ID、模板版本和解析后的组合标识，使恢复、审计、专家委派与记忆归属不依赖当前管理数据反查。

首条用户消息使用现有 Session 消息事件记录。模型可见的员工身份、个性、能力和记忆投影必须继续满足“model-visible 等于 logged”的仓库规则。

历史会话展示创建时记录的员工身份快照。员工后续改名、升级或停用不改写既有会话归属；新会话使用提交时解析的当前有效版本。

## 服务划分

`ui-digital-employees` 提供可提及员工目录、状态投影以及管理页的“开始聊天”动作。`ui-conversation` 保持通用输入与引用机制，通过插件贡献接收数字员工提及来源和路由提交声明，不直接依赖数字员工实现包。

Remote BFF 暴露数字员工任务启动操作。Host 的数字员工管理或 Agent 组合服务拥有员工状态校验、组合解析、根 Agent 创建和首条消息接收。该操作使用现有 Typert namespace 约定，避免方法名与 namespace service 冲突。

员工内部的专家 Agent、Subagent、Skills、Tools 和 MCP 调度保持现状。聊天提及只选择根员工，不允许用户通过提及绕过员工模板和实例授权直接选择内部专家。

## 测试与文档

单元测试覆盖提及列表、首位置约束、单员工限制、失效员工、草稿保留、重复提交和成功导航。Host 测试覆盖激活状态、模板缺失、权限解析、首条消息提交和失败清理。Remote 测试覆盖请求与返回类型以及 namespace 装配。

Web 端到端测试覆盖从聊天输入 `@`、选择员工、提交任务到进入新会话的完整流程，以及从管理页“开始聊天”进入同一流程。数字员工 runnable example 和 keyless snapshot 增加首条用户任务及员工归属证据。

用户文档说明数字员工的创建、激活、聊天提及、后续对话和管理页职责。架构文档补充聊天入口到员工 Agent 组合的调用路径，但不改变 agent-loop。

## 非目标

- 不支持在当前普通会话中临时委派给数字员工。
- 不支持一条消息选择多个数字员工。
- 不支持通过 `@` 直接选择专家 Agent 或 Subagent。
- 不支持依赖纯文本员工名称的 Host 路由。
- 不改变员工的专家、记忆、能力授权或 MCP 配置模型。

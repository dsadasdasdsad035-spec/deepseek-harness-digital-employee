# 管理数字员工

[English](digital-employees.md) | 中文

从 Web UI 侧边栏打开**数字员工**。该工作区管理持久化员工实例，Host 则负责生命周期、权限、记忆、专家、升级、导入与导出验证。

## 创建并激活

选择一个已注册的模板版本，输入显示名称和可选的个性覆盖，再从模板声明的能力中选择授权。创建操作会产生一个固定到该精确模板版本的非活跃实例。检查实例后，先将其激活，再开始工作。

## 配置模板

当 Host 启用本机管理员配置时，可在数字员工工作区中选择**模板配置**。创建包含指令、能力、MCP 引用、专家定义和创建时记忆种子的草稿。预览或发布前请先验证草稿；验证会报告不可用引用和权限错误，但不会暴露凭据值。

Skill 选择器会合并市场已安装 Skill 与本地运行时 Skill。市场条目会显示版本、作者、标签和激活提示。已安装 Skill 在 Host 运行时激活前保持禁用，本地 Skill 则可立即选择。如果草稿仍引用已卸载 Skill，请在验证前移除该不可用引用。

Tool 与 MCP 选择器遵循相同的可用性规则。本地参考工作流可从**市场**安装可直接安装的示例，保存 MCP 凭据引用，然后重启 Host，之后才能选择需要重启激活的 Tool 或 MCP 资产。示例 Tool 发布者只用于测试，开发 Host 必须显式信任它；生产默认配置不会信任它。

预览会组合临时员工 Session，不会修改员工实例或持久化记忆。发布会创建不可变的本地模板版本，并显示在普通模板选择器中。现有员工保持固定版本，直到其升级经过显式审查并被应用。

## 开始员工聊天

打开一个新任务，并在任何任务文本之前输入 `@`。选择器会显示数字员工的身份、模板与可用性。选择一名活跃员工，然后输入任务和可选图像。员工选择是由稳定员工 ID 支持的结构化状态；其可见标签不会发送给模型。

一个新任务只能由一名员工负责，而且员工必须保持在首个语义位置。现有会话不接受员工提及。提交空文本且没有图像时，不会创建员工 Session。

Host 会验证员工处于活跃状态，并且其精确模板组合仍然可用，然后在一项操作中创建员工拥有的根 Session，并把任务作为首条用户消息接纳。Web UI 只有在接纳后才打开返回的会话。如果验证、附件接纳、取消或首条消息处理失败，当前员工选择、草稿与附件会保留在编辑器中，而且不会遗留可用的空员工 Session。

在员工管理工作区中选择**开始聊天**，可打开一个独立的新任务编辑器并预选该员工。提交任务内容前，此操作不会创建 Session。

已接纳的任务使用模板的 preset、指令、显式 skill 与 MCP server、检索到的员工记忆，以及员工的有效权限。

## 使用专家

专家视图列出员工的具名专家。委派使用现有 subagent 运行时；任务树显示一次性与可继续的后代。可继续的专家必须从其直接父任务继续或打断。

## 检查记忆与审计

记忆视图列出员工拥有的任务、Session 与长期记录。删除记录只影响该员工。敏感或超过保留期的提升候选项可能被 Host 策略拒绝。

审计视图记录可归因的管理与任务决定。每个员工拥有的根 Session 都会记录创建时的员工 ID、模板 ID 与版本，以及解析后的组合 ID。模型可见的身份、指令、记忆投影、专家结果与记忆决定会保留为 Session 事件，因此回放可以重建相同输入，而且员工重命名、升级、停用或移除后，历史归属仍会保留。

## 升级、导出与导入

注册新模板版本后，员工仍固定到原版本。先预览升级以检查能力变化，再使用经过明确审查的授权应用升级。

导出会创建一份不含凭据的可移植产物。导入会分配新的员工身份并创建非活跃实例；使用前应检查并激活它。

停用员工可阻止新任务。删除操作会使员工进入 deleting 状态，并且只有在自有工作全部结束后才完成。

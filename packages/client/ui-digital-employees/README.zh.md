# @deepseek-ai/dsh-client-ui-digital-employees

[English](README.md) | 中文

通过生成的 `digitalEmployees` Remote 命名空间检查和操作持久化数字员工实例的浏览器工作区与聊天入口集成。

本包注册侧边栏底部入口，在打开时占用 `shell.application`，向新任务的 `@` 选择器贡献数字员工，并负责员工聊天的路由提交。生命周期、任务接纳、记忆、专家、任务树、审计、升级、导入和导出的权威逻辑均保留在 Host。

## 工作区

该工作区列出已注册模板与持久化实例，提供生命周期命令，并为选中员工打开记忆、专家、任务树、审计、升级、导入与导出视图。它的**开始聊天**操作会打开一个独立的新任务编辑器并预选该活跃员工；用户提交任务内容前，不会创建员工 Session。

破坏性操作需要 UI 明确确认。应用升级前必须先预览，导入会创建新的非活跃实例，导出产物不含凭据。

## 聊天入口

在新任务编辑器的首个语义位置输入 `@` 时，发现列表会显示员工身份、模板与当前可用性。选择活跃员工会插入一个携带稳定实例 ID 的结构化路由引用。该引用不会进入模型可见文本；编辑器不能选择第二名员工，也不能把员工所有者移动到任务内容之后。

提交操作使用剩余文本与图像调用 `digitalEmployees.startChat`。只有 Host 接纳后，客户端才会清除已提交草稿并选中返回的会话。验证、接纳或取消失败时，员工引用、草稿与附件都会保留，供用户修正或重试。现有会话继续使用普通 Session 投递，不能通过提及获得员工所有者。

## 模型体验

### 浏览器发起的工作

#### 模型看到的内容

开始聊天或继续专家会调用 `digitalEmployees` Remote 方法；Host 拥有的员工 Consumer 决定提示词、工具、权限与已记录的 Session 事件。结构化员工引用仅属于路由状态，绝不会进入提示词文本。

#### Token 影响

浏览器包不增加 token，只发送所选管理操作需要的用户内容。

#### KV Cache 影响

浏览器包不直接影响缓存。

## 已知限制与后续工作

- **需要 Host 连接**：工作区没有离线变更路径，生成的 Remote 命名空间不可用时无法管理员工。

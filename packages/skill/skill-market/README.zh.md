# `@deepseek-ai/dsh-skill-market`

[English](README.md) | 中文

宿主侧参考文档：在用户技能目录中安装、升级、列出和卸载市场管理的技能，并读取其宣传图。

插件通过共享 `/api` 载体公开生成的 `skillMarket` Typert Remote。浏览器代码通过 `@deepseek-ai/dsh-api-remotes` 使用客户端安全类型；压缩包校验、文件系统变更和管理权限仍由本宿主包负责。

## 插件

插件提供 `ctx.skillMarket`。其 `list`、`install`、`banner` 和 `uninstall` 方法把已声明的业务失败作为可辨识结果返回。传输取消、载体失败和意外实现错误会拒绝调用，不会伪装成市场结果。

### 配置

| 字段 | 默认值 | 含义 |
|---|---|---|
| `installRoot` | DSH 用户技能目录 | 包含市场目标的绝对目录。默认值与文件系统技能提供器发现的用户目录相同。 |

## 技能包布局

上传的 ZIP 必须在压缩包根目录直接包含一个技能，或者只包含一个包裹该技能的目录。移除可选包裹目录后，`SKILL.md` 必须恰好位于技能包根目录。

校验器拒绝混合根文件、多个根目录、规范化后重复的路径、空名称、绝对路径、盘符路径、UNC 路径、反斜杠、NUL 字节、`.` 和 `..` 路径段，以及普通文件和目录以外的条目。压缩包文件名不决定技能名称。

## 市场元数据

`SKILL.md` 使用常规技能 frontmatter，并且必须提供有效的 `name` 和 `description`。描述文件中的名称是安装标识；存在包裹目录时，两者必须匹配。

可选展示元数据位于 `metadata.marketplace`：

```yaml
---
name: my-skill
description: One-sentence user-visible summary.
metadata:
  marketplace:
    version: 1.2.3
    author: DeepSeek
    tags:
      - tools
      - files
    banner: banner.webp
---
```

版本、作者、标签和宣传图字段均有固定范围并接受严格解析。未知市场字段会导致校验失败，避免拼错字段后静默改变安全或展示行为。

## 宣传图

`metadata.marketplace.banner` 指向技能目录内一个规范化的相对路径普通文件。支持 PNG、JPEG、WebP 和 GIF，不支持 SVG。

安装时会校验扩展名、魔数和大小。`banner` 返回 base64 字节与媒体类型前，会再次校验路径包含关系、普通文件类型、大小、扩展名和签名，因此外部文件系统修改不能把曾经合格的路径变成不安全响应。公开结果不会暴露宿主绝对路径。

## 固定安全限制

| 资源 | 上限 |
|---|---:|
| 解码后的 ZIP | 10 MiB |
| 普通文件 | 256 个 |
| 单个解压条目 | 30 MiB |
| 解压后总数据 | 30 MiB |
| 宣传图 | 2 MiB |

这些数值是协议安全不变量，不是部署配置。ZIP 解析前会完成严格 base64 解码和解码后大小检查；流式解压在发布前同时约束声明大小与实际大小，并在结构或资源校验失败后停止。

## 结构化结果

成功方法通过生成的 Remote 结果返回类型化值。预期失败使用封闭的 `SkillMarketFailure` 联合，包括压缩包或描述文件无效、资源超限、不安全条目、宣传图无效、需要确认受管升级、非受管冲突、清单不兼容、技能不存在和目标不受管理。

调用方按 `error.code` 分支，绝不解析诊断文本。初次安装不会替换已有目标。只有有效的受管目标可以返回 `managed-upgrade-required`，此后调用方可带明确替换意图重新提交。非受管、格式错误、不兼容或名称不匹配的目标保持不变。

## 清单所有权

每个已发布的市场安装都包含 `.dsh-market.json`，其中记录 `schemaVersion: 1`、精确技能名称、规范化展示与宣传图元数据、源文件名和安装时间。该严格清单是升级和卸载的唯一权限依据。

列举操作忽略缺少清单、清单格式错误、版本不兼容或名称不匹配的目录。变更操作在持有技能锁时重新检查清单，并拒绝所有权不确定的目标。手工放置的技能仍可由文件系统提供器发现，但市场不能替换或删除它们。

## 原子生命周期

操作通过按规范化技能名称分键的进程内互斥锁串行化；不同名称可并行推进。不依赖目标状态的校验可以在加锁前执行，最终所有权检查、发布或分离、回滚和成功判定都在锁内完成。

安装先写入并验证私有的同级暂存目录，其中包括管理清单，再将其重命名到不存在的目标。升级先把受管目标重命名为同级备份，通过同文件系统原子重命名发布暂存目录；发布失败时恢复备份，成功后才删除备份。卸载先把受管目标重命名为同级墓碑目录，再执行受控的递归清理。

成功发布或分离后，网关为已提交的用户技能路径发出 `skill-filesystem/host-mutation`。文件系统提供器沿其注册记录所拥有的失效路径处理该事件，因此下一次发现读取无需依赖文件监听时序即可看到安装、升级或移除结果。校验失败、提交失败和已经恢复的回滚不会发出成功变更通知。

进程崩溃可能留下保留命名的暂存、备份或墓碑同级目录。自动清理崩溃残留会等到清理动作可绑定持久事务记录后再实现；服务不会根据看似保留的文件名猜测所有权。

## 模型体验

不存在模型可见性，因为压缩包校验和文件系统变更不会改变提示词投影、模型请求或会话日志。

#### KV Cache 影响

市场操作不会添加或修改请求历史。

## 已知限制与延后工作

- 第一版 Remote 以 base64 JSON 传输压缩包；解码后 ZIP 上限约束浏览器和宿主的内存使用。
- 每个技能最多有一张宣传图，版本仅是展示元数据，不表示依赖或更新策略。
- 市场不提供托管注册表、URL 下载、评分、签名、依赖解析或自动更新。
- 市场不安装项目、预设或内置技能，也不会在校验期间执行技能。
- 市场不改变文件系统技能优先级、agent-loop 行为、会话事件或格式、模型请求、提示词投影，也不改变 TypeScript 和 Python SDK。

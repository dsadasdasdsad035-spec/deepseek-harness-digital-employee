# 完成开发分支

## 概述

通过呈现清晰选项并处理所选工作流来指导完成开发工作。

**核心原则：** 验证测试 → 呈现选项 → 执行选择 → 清理。

**开始时宣布：** "我正在使用 finishing-a-development-branch 技能完成此工作。"

## 流程

### 第一步：验证测试

**在呈现选项之前，验证测试通过：**

如果测试失败：停止。在测试通过之前不能继续。

### 第二步：呈现选项

呈现恰好这 4 个选项：

```
实现完成。你想做什么？

1. 本地合并回 <基础分支>
2. 推送并创建 Pull Request
3. 保持分支原样（我稍后处理）
4. 丢弃此工作

选择哪个？
```

### 第三步：执行选择

#### 选项 1：本地合并
```bash
git checkout <基础分支>
git pull
git merge <功能分支>
# 验证测试
git branch -d <功能分支>
```

#### 选项 2：推送并创建 PR
```bash
git push -u origin <功能分支>
gh pr create --title "<标题>" --body "..."
```

#### 选项 3：保持原样
报告："保持分支 <名称>。工作树保留在 <路径>。"

#### 选项 4：丢弃
**先确认：**
```
这将永久删除：
- 分支 <名称>
- 所有提交：<提交列表>
- 工作树在 <路径>

输入 'discard' 确认。
```

等待确切确认。

### 第四步：清理工作树

选项 1、2、4 后：
```bash
git worktree remove <工作树路径>
```

选项 3：保留工作树。

## 警示信号

**永远不要：**
- 在测试失败时继续
- 不验证结果就合并
- 不确认就删除工作
- 未经明确请求就强制推送

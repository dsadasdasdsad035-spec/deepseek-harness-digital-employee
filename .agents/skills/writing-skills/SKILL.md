# 编写技能

## 概述

**编写技能就是将测试驱动开发应用于流程文档。**

你编写测试用例（带子代理的压力场景），看它们失败（基线行为），编写技能（文档），看测试通过（代理遵从），然后重构（关闭漏洞）。

**核心原则：** 如果你没有看到代理在没有技能的情况下失败，你不知道技能是否教了正确的东西。

## 铁律

```
没有失败的测试，就没有技能
```

这适用于新技能和对现有技能的编辑。

## SKILL.md 结构

**前置元数据（YAML）：**
- 两个必需字段：`name` 和 `description`（最多 1024 字符）
- `name`：只使用字母、数字和连字符
- `description`：第三人称，只描述何时使用（不描述它做什么）
  - 以"Use when..."开头
  - **永远不要总结技能的流程或工作流**

```markdown
---
name: 技能名称
description: Use when [具体触发条件和症状]
---

# 技能名称

## 概述
这是什么？1-2 句核心原则。

## 何时使用
## 核心模式
## 快速参考
## 常见错误
```

## Claude 搜索优化（CSO）

**描述 = 何时使用，而不是技能做什么**

```yaml
# 错误：总结工作流
description: Use when executing plans - dispatches subagent per task with code review

# 正确：只有触发条件
description: Use when executing implementation plans with independent tasks
```

## 红-绿-重构用于技能

### 红色：编写失败测试（基线）
在没有技能的情况下运行压力场景。记录确切行为和合理化借口。

### 绿色：编写最小技能
编写针对那些具体合理化借口的技能。运行相同场景验证代理现在遵从。

### 重构：关闭漏洞
代理找到新的合理化借口？添加明确的反驳。重新测试直到无懈可击。

## 技能创建检查清单

**红色阶段：**
- [ ] 创建压力场景（纪律技能需要 3+ 个组合压力）
- [ ] 在没有技能的情况下运行场景——逐字记录基线行为

**绿色阶段：**
- [ ] 名称只使用字母、数字、连字符
- [ ] description 以"Use when..."开头，包含具体触发条件
- [ ] 解决红色阶段识别的具体失败
- [ ] 带技能运行场景——验证代理现在遵从

**重构阶段：**
- [ ] 识别新的合理化借口
- [ ] 添加明确的反驳
- [ ] 重新测试直到无懈可击

# Agent Note: 市场数字员工参考工作流

Status: implemented

[English](2026-09-02-marketplace-digital-employee-reference-workflow.md) | 中文

## 问题

Skill、Tool 与 MCP 市场具有不同的信任、激活和凭据规则。彼此独立的包测试无法证明管理员可以安装三类资产、重启 Host、发布一个模板、创建员工，并通过产品 `@` 聊天路径仅使用选中的能力。只使用浏览器场景又会使压缩包安全与运行时归属失败难以诊断。

## 决策

仓库拥有三个确定性的可安装示例：`marketplace-test-skill`、注册 `marketplace_test_echo` 的签名 Tool 包，以及声明式 `marketplace-test-mcp` 包。作者模板继续作为包含占位符与签名说明的独立下载。Tool 示例使用固定的测试专用 Ed25519 发布者；除非开发或测试配置显式提供该公钥，否则生产信任保持为空。私钥只属于生成 fixture（测试前置数据），市场运行时绝不加载它。

MCP 示例声明 `MARKETPLACE_TEST_MCP_ENDPOINT` 与 `MARKETPLACE_TEST_MCP_TOKEN` 引用。Web 与组装测试把 endpoint 解析到使用临时端口的本机 Streamable HTTP 服务，并通过普通凭据提供方解析凭据。已安装包数据、配置草稿、目录投影、Session 事件与审计记录包含引用名称，但不包含解析后的凭据值。由凭据拥有的请求头不会进入固定请求头投影。

Tool 与 MCP 安装仍需重启后激活。Web scaffold 在一次干净的 Host 停止和重新启动之间保留同一个临时 Harness Home，而每个生命周期分别拥有隔离的配置工作室文件、员工存储、市场目录、凭据与 Skill 根目录。这样既证明预期的重启持久化，也不会导入开发者状态。

验证按所有权拆分。聚焦包测试验证压缩包、签名、生产默认信任拒绝、endpoint 与凭据引用、确定性 Tool 和 MCP 响应、目录关联、模板验证与员工权限。headless 无密钥快照负责模型可见组合、调用、拒绝已安装但未声明的 Skill、持久 Session 证据与审计归属。Web e2e 负责从下载和上传到重启、模板发布、员工激活、首位 `@` 选择、对话完成与员工归属保持的用户流程。

## 曾考虑的替代方案

**把作者模板作为可安装示例。** 带占位符的标识与签名适合作者指导，但无法保持原样安装，也不应复用为 fixture 标识。

**默认信任示例发布者。** 随产品分发只能证明仓库拥有该 fixture，不能证明部署授权执行该发布者的包。显式测试配置可保持生产信任不变。

**在 MCP 压缩包中嵌入 URL 或凭据值。** 固定外部 URL 会使工作流依赖网络，嵌入凭据则会产生第二条密钥存储路径。引用同时保留离线确定性与 Host 所有权。

**只在浏览器中覆盖整个工作流。** 浏览器失败会混合压缩包验证、重启激活、运行时组合与归属。聚焦测试与组装快照使各类失败保持局部，而 Web e2e 证明真实管理员路径。

## 后果

贡献者获得一条覆盖三类市场与数字员工组合的可复现无密钥参考工作流。这些示例属于测试资产，不构成第三方兼容性承诺。Tool 执行要求显式信任测试发布者，Tool 与 MCP 激活需要真实 Host 重启，MCP fixture 要求配置 endpoint 与凭据引用。分层测试增加了包、快照与浏览器套件的维护成本，但每一层只验证其能够权威观察的行为。

# Agent Note: 数字员工聊天采用结构化路由与原子启动

Status: implemented

[English](2026-08-29-digital-employee-chat-routing.md) | 中文

## 问题

聊天入口需要在根 Session 存在之前选择一名持久化数字员工。解析显示文本无法保留稳定归属，而在接纳首条消息之前创建 Session，会在验证或接纳失败时暴露空员工工作。从员工管理开始工作也需要与直接聊天选择汇入同一路径，同时不能替换无关草稿，也不能创建另一条任务路径。

## 决策

新任务编辑器把员工选择表示为一个携带稳定员工实例 ID 的结构化路由引用。该引用只在首个语义位置有效，只允许存在一个路由所有者，而且其标签绝不会进入模型可见内容。通用输入系统负责编辑、失效、撤销、重试结算与路由声明仲裁；数字员工客户端负责发现、可用性显示、员工验证提示与提交。

客户端通过 `digitalEmployees.startChat` 发送剩余文本与图像，同时携带调用方生成的 Session 和提交身份。Host 重复执行权威的员工与模板验证，解析[数字员工组合决策](2026-08-28-digital-employee-composition.zh.md)所述的组合，创建根 Agent，接纳附件，并在一项操作中排入标准的首条用户消息。相同重试共享已接纳结果。使用不同任务数据复用提交身份会被拒绝；任何验证、取消、附件或消息接纳失败都会 dispose 未发布的工作，而不会返回可用的空员工 Session。

浏览器只有在 Host 接纳后才会清除已提交的编辑器并选中返回的 Session。启动失败或被中止时，路由引用、任务文本与附件都会保留。管理工作区提供**开始聊天**操作，用于打开一个独立的新任务编辑器并预选该员工；在用户提供任务内容并提交之前，不存在 Host 员工 Session。

## 持久归属

根 Session 会在发布前记录必读的 `digital-employee/identity` 事件，其中包含员工实例 ID、模板 ID 与版本、解析后组合 ID，以及创建时的展示数据。首项任务内容仍然是普通的 `user/message` 事件。因此，恢复过程从持久身份而非当前显示文本读取归属；之后的重命名、升级、停用或移除不会改写历史归属。专家与 subagent 工作仍可归因到该员工拥有的根 Session 及其有效权限。

## 考虑过的替代方案

- **在 Host 解析纯文本 `@name`**：名称可能变化或冲突，而且文本无法携带稳定实例身份，也不能参与编辑器失效处理。
- **先创建员工 Session，再通过第二项操作发送首条消息**：部分失败会暴露空的员工自有 Session，并把提交幂等性拆分到两次调用中。
- **从管理工作区创建空员工 Session**：打开管理入口会在用户提供工作之前产生持久变更，而且与直接聊天选择采用不同的失败路径。
- **允许在现有会话中提及员工或选择多名员工**：归属、记忆、权限与审计归因需要一套编排模型，而不再是单一根任务所有者。

## 结果

通用编辑器获得插件自有的路由提交机制，而无需导入数字员工领域。选择器可用性只提供交互提示，Host 仍在提交时拥有权威。已接纳的启动会发布一个带首条消息、可归因的根 Session；被拒绝的启动保留用户来源状态，并且不遗留可用的空员工 Session。管理入口与直接 `@` 入口共享同一条验证、接纳、重试与导航路径。

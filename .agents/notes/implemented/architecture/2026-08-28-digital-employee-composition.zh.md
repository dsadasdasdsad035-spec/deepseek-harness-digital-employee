# Agent Note: 数字员工组合复用现有 agent 运行时并采用持久化实例

Status: implemented

[English](2026-08-28-digital-employee-composition.md) | 中文

## 问题

数字员工把可复用指令与可变身份、授权、记忆、生命周期及专家工作组合在一起。如果把这些内容视为一个可变对象，模板更新就会改写员工历史；如果另建员工执行引擎，则会重复实现 Agent 与 subagent 的调度、续跑、取消和持久化。当 preset、MCP server、skill 与专家由独立注册的插件组合时，权限和模型可见状态也需要始终有效的规则。

## 决策

数字员工模板是不可变的可执行定义，由模板 ID 与精确版本标识。持久化实例保有独立的身份、显示名称、个性覆盖、授权、生命周期状态、记忆与审计历史，并继续固定到所选模板版本。注册新模板版本不会修改实例；升级是显式的预览与应用操作，用于审查能力变化和授权。

Agent Consumer 在创建 Session 前解析活跃实例，并通过现有 Agent preset、作用域化注册与 subagent 运行时完成组合。具名专家是现有 subagent 执行的描述符，其中包括可继续的子级；它们不会引入员工调度器、子级协议或 agent-loop 分支。

## 权限

权限是显式且单调收紧的。根员工只获得模板声明并由实例授予的能力。专家获得其声明、员工有效权限与父 Agent 权限三者的交集。委派深度、并发与超时限制只能随着工作下沉而收紧。缺少 skill 或 MCP 引用时解析失败，不会回退到环境注册项。

## 持久化模型输入

每一项可能进入模型请求的员工专属值都从 Session 事件重建。身份、带版本的指令、有界记忆投影、专家请求、拒绝、子级身份、结果与记忆决定事件携带用于提示词或历史渲染的 payload。审计记录支持管理问责，但不能替代用于模型回放的 Session 日志。

## 考虑过的替代方案

- **把模板和可执行配置复制到每个实例**：这会重复定义、掩盖实际执行的版本，并把模板修正变成可变实例迁移。
- **另建员工与专家运行时**：这会重复 Agent 发布、生命周期、续跑、取消、持久化与 subagent 语义，同时产生一条绕过 agent-loop 扩展的路径。
- **合并继承权限与环境权限**：这会让 preset 或全局挂载能力超出经过审查的员工与父级授权。
- **只在提示词或审计记录中保留员工上下文**：两者都无法在 Session 回放期间重建精确的模型输入。

## 结果

模板作者发布新的不可变版本；操作方显式升级实例。Provider 负责可变持久化与策略，Consumer 负责 Agent 组合与 Session 投影。Host 与 Web 管理层保持为这些服务之上的适配器。测试覆盖注册表 dispose、Provider 持久性与生命周期、权限交集、组装后的模型可见事件、SDK 投影与浏览器管理旅程，而无需第二套执行栈。

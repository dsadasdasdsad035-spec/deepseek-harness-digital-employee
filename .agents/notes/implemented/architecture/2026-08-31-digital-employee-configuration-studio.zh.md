# Agent Note: 数字员工配置将可变草稿与不可变运行时版本分离

Status: implemented

[English](2026-08-31-digital-employee-configuration-studio.md) | 中文

## 问题

本机管理员需要编写可复用的数字员工模板，同时不能把能力设计、凭据处理与发布机制暴露给普通员工。草稿可以不完整并被反复编辑，而员工实例需要稳定、可解析且权限可审查的模板版本。

## 决策

仅当管理 Host 的本机 `administrator` 配置为 true 时，才启用配置工作室。私有 `studioFile` 保存可变草稿和发布溯源记录，现有数字员工注册表保有不可变且可运行的版本。每次发布都会重新验证选定的草稿修订版，在版本专属目录中实体化根指令和专家指令，并注册所得的文件型模板版本。持久化发布是提交点：`studioFile` 写入失败会撤销候选注册并删除其实体化目录，因此重试仍会获得同一个下一版本。

预览组合复用同一数字员工 Agent Consumer，并使用临时实例、带预览标记的 Session、隔离的归属信息和临时实体化目录。显式 dispose 或管理插件 teardown 都会等待 Agent 停止并删除文件。已发布模板的注册也由管理插件持有，并在 teardown 时离开运行时注册表。预览 Session 不会出现在普通 Session 订阅中，也不会持久化员工记忆。

本地发布版本仍可通过既有模板列表、员工创建和显式升级审查选择。记忆种子会随发布版本保存，并只在员工实例存在后以配置溯源信息提升。任一记忆种子无法提升时，创建操作会删除新实例。

## 考虑过的替代方案

- **把模板注册表作为草稿存储**：注册表条目必须完整且不可变，才能在执行和升级审查中解析精确版本。
- **在运行时模板中内联保存编写的指令**：运行时指令溯源采用文件形式，新增第二种内联形式会产生不同的组合路径。
- **使用持久化的非活跃员工进行预览**：探索性 Session 和记忆活动可能作为业务数据可见。
- **在创建员工前写入记忆种子**：记忆归属需要实例身份，创建失败会留下孤立记录。

## 结果

管理员获得本机编写流程，无需在浏览器中保存凭据，也不会产生可变模板版本。普通用户继续使用既有操作工作区。发布产生由具体版本持有的材料，失败提交不会留下已注册版本，预览与注册可确定性清理，升级仍保留显式审查步骤。聚焦的 Host 与 Web 测试及组装式无密钥快照固定草稿验证、提交回滚、teardown 释放、版本解析、创建时记忆提升与升级审查行为。

# Agent Note: 公司活世界（注册表、碰撞、情绪、到访史、绑定屏幕）

Status: implemented

[English](2026-09-14-company-living-world.md) | 中文

## Problem

3D 公司世界此前是演出：车穿车、员工穿家具、没有记录"谁来过哪里"、电脑是道具。用户要求一个活世界——每个实体有定位与边界、互相碰撞不可穿透；数字员工实例有"真实存在"的持久证据（刷新后仍在的到访史；车辆按设计保持刷新随机）；情绪由碰撞滋养、破坏纯视觉；电脑与员工绑定并显示其真实会话内容。

## Decision

- **一个客户端实体注册表，按类碰撞策略。** `scene.ts` 的 `EntityRegistry` 登记 `{id, kind fixture|car, position, halfExtents, destructible?, damage, object?}`；构建器以世界坐标登记设施（茶水台、休息区沙发/茶几、厕所洗手池、吸烟区长凳/烟灰缸、每名成员的工位桌与电脑——经 `spawnNpcs` 登记以取得房间原点）。车辆采用同边跟车间距（前车 6 单位内后车保持——排队不穿透）；NPC 每步探测 `blockingFixture`（先沿 x 后沿 z 滑行；全阻累积情绪，6 次后重新规划；倒塌残骸可通行）；行走者两两拥挤（<0.7 一方让行，双方加情绪）。不做通用物理引擎。
- **持久到访史证明实例连续性。** `dsh-digital-employee-file/whereabouts` 拥有 `whereabouts.json`（文件锁+原子写、最新在前、上限 50）；群网关在 `companyGroups` 命名空间暴露 `reportEmployeeVisit`/`employeePresence`；场景在每次到达功能区与返回工位时触发上报（地点名 茶水区/休息区/厕所/吸烟区/工位，绝不记逐帧坐标）。位置保持纯表现；到访记录粗粒度、廉价、对人可读。
- **情绪运行时化，破坏纯视觉。** 情绪 0–100 由拥挤与受阻累积、1.5/秒衰减；≥50 显示 😡 头顶标记；≥85 路过者 40% 踹可破坏设施 → damageStep 推进 完好→受损（歪斜下沉）→倒塌（翻倒可通行）。无玩法后果、无修复循环、刷新重置。
- **绑定电脑显示真实会话尾部。** `CompanyFloorMember.chatTail` 折叠员工最新会话的尾部 assistant 文本（活跃库优先，持久层缓存机会性预热；管理网关测试桩的裸对象被容忍）；客户端把最近文本绘制到忙碌屏旁的 canvas 纹理侧板上。

## Alternatives considered

- **通用物理引擎** —— 平面就是走廊+门洞；三条窄策略（车间距、AABB 探测、两两让行）以可忽略成本交付可见物理。
- **会话日志式到访事件** —— 位置不进模型请求；每到访一条的文件记录才是"实例来过"的诚实粒度。
- **持久化损坏** —— 用户选纯视觉损坏；持久化需要所有权、修复与迁移，换不来玩法价值。

## Consequences

触及套件 57 测试全绿（注册表碰撞表、到访史存储、网关 presence remotes、群+管理+控制台套件）；快照回放、doc-sync（28）、hygiene（13）、lint/typecheck/build 全绿；3080 运行该构建。依赖运动的实机验证（游走、到访、破坏）被已知的 IAB 遮挡问题阻塞（标签页隐藏时 rAF 挂起——画布冻结），这些视觉效果留给用户屏幕；确定性单测覆盖机制。途中发现并修复一个真实缺陷：网关的 apiproxy 类型导入造成 doc-graph 依赖环——网关现仅经结构化 `ctx.inject`/`ctx.get` 访问 API 网关、无包边，环消失。已知限制：NPC 拥挤 O(n²)（仅房间规模名单）、情绪不持久、冷会话的聊天尾部晚一轮预热。推迟项：行人 NPC、修复循环、损坏影响玩法、到访原因。

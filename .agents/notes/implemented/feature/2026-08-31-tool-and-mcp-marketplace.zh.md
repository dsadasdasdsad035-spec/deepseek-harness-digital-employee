# Agent Note: 受信任的工具与 MCP 市场

Status: implemented

[English](2026-08-31-tool-and-mcp-marketplace.md) | 中文

## Problem

仅安装技能无法为管理员提供安全获取可执行工具或带凭据 MCP 客户端的路径。数字员工模板中的自由文本标识也无法展示可用性、权限、重启状态和未解析依赖。

## Decision

Web 市场包含技能、工具和 MCP 三个标签页。工具包与 MCP 包使用独立的版本化描述符，并共享有界 ZIP、规范化路径、托管清单、SHA-256 文件表、Ed25519 信任、按键串行变更和原子发布实现。

工具上传和安装不会执行包内代码。安装、升级或卸载成功后会报告需要重启。新的 Host 组合会再次验证已安装描述符、签名和文件哈希，然后才导入工具插件入口。

MCP 包是声明式 Streamable HTTP 定义。配置只持久化凭据引用名称；解析后的值仅在 `McpClientManager` 挂载已配置服务时存在。激活以单个包为原子单位：包内全部已声明服务都成功挂载后，该包才变为可用；后续服务失败会按逆序 dispose 先前的挂载。市场清单、模板记录、诊断和 Remote 响应都不包含解析后的值。

数字员工专业配置台使用一个管理员目录，合并已安装技能、已注册工具、托管 MCP 配置和已有的未解析引用。新选择必须是员工权限内的可用资产。已有未解析值保留为可移除诊断，不会清除专家、记忆或委派配置。

发布者模板包含描述符示例、签名文件表输入、权限声明、仅凭据引用的 MCP 请求头和签名说明。Web bundle 从 `DSH_MARKET_TRUSTED_PUBLISHERS` 读取受信任发布者记录。

## Alternatives considered

- **热加载上传的工具代码**：这会让归档变更立即获得代码执行权限，并使回滚无法恢复运行中的进程。
- **接受任意 MCP 命令或原始配置**：这会破坏稳定验证，并允许包数据混合连接声明、凭据或可执行行为。
- **继续使用自由文本模板能力标识**：这无法展示权威的可用性与权限状态，也无法防止意外授权未解析资产。
- **所有资产共用一个通用描述符**：共享字段无法消除技能、工具和 MCP 客户端在激活、凭据和权限规则上的差异。

## Consequences

管理员可以通过可发现清单获取和授权每类能力，同时由 Host 验证托管目录所有权和凭据保密。激活失败后，任何 MCP 包都不会只暴露其中一部分服务。工具与 MCP 变更不会立即激活，部署方必须维护受信任发布者密钥，并在包生命周期变更后重启 Host。MCP 传输目前仅支持 Streamable HTTP。

# Agent Note: Company group chat on the agent-loop spine

Status: implemented

English | [中文](2026-09-15-company-group-on-agent-loop.zh.md)

## Problem

Of the three conversation surfaces, ordinary chat sessions and digital-employee 1:1 chats both ran the standard spine — one session, one root agent, one resident loop — while the company group was the sole bypass: `ensureGroup` created a bare session with no root agent, apiproxy's `prompt` short-circuited through an injected `groupDelivery` hook, and every employee utterance ran in a throwaway `session-group-turn-<uuid>` session that was disposed after one text was copied back. The cost, confirmed by code reading: no streaming, no cancel, per-turn amnesia (the situation prompt restated everything), invisible tool calls, an in-process `turnChain` whose queued turns died on restart, and group events that could never enter any model's context.

## Decision

- **The group session gets a Lead root agent and the standard send path.** `ensureGroup` creates (or cold-resumes) a real agent on the deterministic group session id; user messages arrive via ordinary `session.prompt` → `followup`. The `groupDelivery`/`setGroupDelivery` special case is deleted from apiproxy, its API interface, the api-catalog, and the client fixtures.
- **The Lead is a brainless router; mention routing costs zero model calls.** A listener on the Lead's `agent/pre-step` parses claimed user messages, appends the user-voiced `company-group/message`, queues one `company-group/turn-queued` per `@displayName` match, and returns an enter decision with empty messages — the loop ends a step-0 empty turn as `completed` before `buildRequest`, so mention-free messages never touch a model ("no mention, no reply" falls out of the mechanism).
- **Employees are continuable member sessions, not one-shots.** Each (company, employee) pair owns `session-group-member-<companyId>-<employeeId>` with `origin: 'subagent'` (hidden and fenced from generic routing), created through `digitalEmployeeAgent.createTask` and cold-resumed through a new `resumeTask` (same composition, identity-event guard, no re-append of identity/instruction events). Deliveries inject situation plus a bounded group snapshot (caller-owned framing; the surface union stays closed), run as ordinary streaming tool-capable turns, and the final assistant text is written back as an employee-voiced group message.
- **The queue is the group log.** `turn-queued`/`turn-delivered` events with queued-minus-delivered folding give per-employee serialization, restart replay, roster-leave drops, and the task-broadcast dedup cursor (`dedupKey: task:<seq>`); the in-memory `turnChain`, `runSpeakingTurn`, throwaway sessions, and the race-to-fallback timeout are retired. A timeout now really cancels the member turn, which then settles on the deterministic one-liner like any failure. `cancelCompanyGroupTurn` exposes cancel to the group view.
- **Live progress is an event-projected indicator node, not chunk mirroring.** The chat surface renders `turn-queued` → "正在输入… + 取消" and hides it on `turn-delivered`. Mirroring member `assistant/chunk` events into the group log was rejected: custom events never enter the surface, so the durable mailbox log would grow by the full token stream of every turn, unreduced by compaction. In-transcript chunk-level projection (cross-session composition) is deferred.

## Alternatives considered

- **Moderator Lead (one loop role-plays all employees)** — cheapest loop-wise but surrenders per-employee composition, tools, models, and memory, which are the product's core; rejected.
- **Multi-writer shared session (N loops on one log)** — blocked by the registry's one-agent-per-session identity and the closed surface union; a core-spine change violating "plugins, not loop changes"; rejected for this surface.
- **Productionizing `experimental/agent-team`** — its roster/mailbox solves the same class of problem, but it is experimental, its Lead semantics are "any ordinary runtime root", and members there are generic continuable children while group members need the existing digital-employee composition/deletion/memory machinery. The group needs a subset (serialize, dedup, replay) implemented in ~100 lines of log folding; convergence with agent-team stays open as a future change.

## Consequences

Zero model calls for routing are proven by a real-loop test harness (AgentLoop + MockAdapter): the mention-free test asserts `adapter.requests` stays empty. Member continuity is proven by one `createTask` for two turns with two injected user messages. Cold replay, roster-leave drops, cancel-degrades-to-fallback, and dedup all have dedicated tests (12 in the gateway suite, plus 2 `resumeTask` tests). The keyless assembled snapshot (company-console) now boots the real agent spine, sends through the Lead followup, and refreshed its expected transcript (3 lines). Known limitations: the typing indicator shows no incremental text; employee-to-employee chains remain out of scope; task-broadcast trigger lag stays one poll interval. Deferred: in-transcript chunk projection, agent-team convergence, employee memory refresh on resume.

## Live-service verification (2026-09-15)

An unauthenticated test instance (`dsh web --patch` disabling the accounts/email rows, `$DSH_HOME` pointed at a copy of the real data home, port 3090) was driven end-to-end over the raw `/api` HTTP contract (typert endpoints ride `POST /api/<namespace>/<method>` with `{args}`; core methods `POST /api/session.prompt`). With real DeepSeek calls: mention-free message landed with no trigger and NO `request/header` event in the Lead log (wire-level zero-model-call proof); `@项目经理` produced a real self-introduction; the second mention answered "we just talked about my self-introduction" (member-session continuity with real memory); both deliveries shared one `memberSessionId` and settled; `cancelCompanyGroupTurn` accepted mid-turn and the queue settled on the deterministic fallback line. Two fixes came out of this pass: the gateway's `static inject` must declare `agents` (tests missed it because AgentRegistry loads as a plugin there), and member sessions need the deployment's default model selection (`agentDefaultModel.currentSelection()` passed as `agentOptions` + `modelSelection`) or prompt assembly fails on the persona's `{{model}}` variable — the failure degrades to the fallback line, which is why the first live run "replied" with fallback text.

## Browser-GUI verification (2026-09-15)

Driving the real web UI through the in-app browser surfaced two defects the scripted e2e could not reach, both now fixed and covered:

1. **Typing indicator froze the transcript.** `buildViewNode` returned `null` once settled, but the conversation assembler forbids withdrawing a materialized node (`conversation-assembler.ts` throws "withdrew materialized target"); the `turn-delivered` update then aborted the flush, leaving the "正在输入…" indicator stuck and later messages unrendered. Fix: emit the same node with `visibility: 'hidden'` when settled, never `null`.
2. **Cold-resume router loss.** A browser refresh resumes the group through apiproxy's generic `agentFor`, whose setup only re-composes the session preset — it does not know the session is a company group. The Lead returned without its `agent/pre-step` router and answered `@mention` as an ordinary assistant (the group log gained `request/header` and `assistant/message`). Fix: attach the router in the gateway constructor via `agent/session-start`, which fires on every create/resume path; the listener resolves the opened marker to the company and mounts on `agent.ctx`. Verified by script: after cold resume through `session.list` + `session.history`, an `@mention` still routes to the member with no `request/header` or `assistant/message` in the group log.

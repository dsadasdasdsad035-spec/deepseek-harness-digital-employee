# Agent Note: 受管技能市场

Status: implemented

[English](2026-08-27-managed-skill-marketplace.md) | 中文

## 问题

用户需要通过持久的浏览器工作流查看和变更 DSH 用户目录中的技能，同时不能授予浏览器文件系统权限，也不能让市场操作覆盖手工管理的内容。上传的 ZIP 数据是不可信输入，文件系统发现过程绝不能观察到未完整安装的目录。

## 决策

技能市场是一项由宿主负责、提供生成式客户端 API 和本地化设置贡献的能力。宿主校验压缩包和宣传图，通过版本化清单确定管理权限，串行化冲突目标的变更，使用同文件系统重命名发布或分离目录，并在成功变更后通知文件系统技能提供器。

## Typert Remote

`@deepseek-ai/dsh-skill-market` 通过共享 `/api` 载体上的生成式 `skillMarket` Typert Remote 公开 `list`、`install`、`banner` 和 `uninstall`。客户端安全的请求、结果、清单、标识和失败类型通过 `@deepseek-ai/dsh-api-remotes` 提供，Web 包调用 `ctx.remote.skillMarket`。

预期业务失败使用封闭的可辨识结果联合。载体失败、取消和意外实现错误仍表现为被拒绝的调用。这一区分使本地化和控制流不依赖诊断文本，也避免在生成式 API 旁维护第二套 RPC 生命周期。

## 清单权限

`.dsh-market.json` schema version 1 是唯一变更权限依据。只有当清单是普通文件、按受支持版本严格解析且记录的名称与目标技能完全一致时，目标才受市场管理。列举操作忽略不确定目标；升级和卸载拒绝清单缺失、格式错误、版本不兼容或名称不匹配的目标。

公开清单不包含宿主绝对路径。手工管理目录仍由文件系统提供器发现，但不属于市场替换和递归删除权限范围。

## 分键事务生命周期

按规范化技能名称分键的进程内互斥锁覆盖最终所有权检查、提交或分离、回滚和成功判定。不同名称的操作可独立推进，最后一个等待者离开后会移除锁记录。

安装在原子重命名到不存在的目标前验证私有同级暂存目录。升级先把受管目标重命名到同级备份，再发布暂存目录；发布失败时恢复备份，成功后才删除备份。卸载先把受管目标分离到同级墓碑目录，再进行受控清理。保留的事务名称不符合有效技能名称语法，因此发现过程不会把残留识别为技能。

## 文件系统提供器失效

安装、升级和卸载分离成功后，会为已提交的用户技能路径发出类型化的 `skill-filesystem/host-mutation` 根事件。文件系统提供器通过其注册记录所拥有的失效机制处理事件，因此下一次发现读取无需依赖文件监听时序即可观察到变更。

校验失败、提交失败和已经恢复的回滚不会发出成功变更通知。文件系统监听仍是额外观察路径，重复失效只会再次驱逐缓存，不影响正确性。

## 安全限制

宿主严格解码 base64，并使用具有固定限制的流式 ZIP 处理：解码后的压缩包 10 MiB、普通文件 256 个、单个解压条目 30 MiB、解压后总数据 30 MiB、单张宣传图 2 MiB。这些值是协议安全不变量，不是部署设置。

技能包路径拒绝穿越、绝对路径、盘符路径、UNC 路径、反斜杠、NUL、点路径段、重复路径、混合根和非普通条目。宣传图支持 PNG、JPEG、WebP 和 GIF，并在安装时及以后每次读取时通过路径、普通文件、大小、扩展名和魔数校验。校验过程绝不执行压缩包内容。

## 浏览器工作流

Web 包通过客户端 slots 提供本地化设置导航项和设置区。snapshot store 管理清单、本地元数据搜索、ZIP 预检和编码、受管升级确认、确认卸载、宣传图延迟加载、进度、通知、重试和本地化失败状态。

初次安装不携带替换意图。只有 `managed-upgrade-required` 会保留编码后的候选包并提供确认；非受管或不兼容目标没有强制覆盖操作。generation guard 阻止被取代的异步操作发布状态，取消、成功替换或移除以及销毁都会释放保留的压缩包或图片数据。

## 崩溃残留

运行中的事务会约束清理失败并记录诊断，但进程崩溃可能留下暂存、备份或墓碑同级目录。启动时不会仅凭保留命名删除路径。自动恢复保持暂缓，直到每次清理判定都能关联持久事务记录。

## 未变更的产品层面

技能市场变更现有用户技能目录，并把发现委托给文件系统提供器。它不增加会话事件或格式变更、模型请求输入、提示词投影、agent-loop 行为，也不改变 TypeScript 和 Python SDK。

## 考虑过的替代方案

**独立 Connection 通道。** 专用 `/skill-market` 路由会重复 Typert Remote 已经提供的路由、生命周期、生成和错误处理。

**在消息中编码错误。** 解析诊断文本会让浏览器控制流和本地化依赖不稳定文本，而不是穷尽类型。

**用户目录中的所有技能都受管理。** 目录位置本身不能授权替换或递归删除用户编写的内容；严格清单提供明确所有权。

**直接解压到目标。** 发现过程可能观察到不完整或已拒绝的文件，回滚也无法恢复完整旧安装。

**一个全局市场锁。** 不同技能名称不共享目标状态，全局串行化只会降低并发而不能提高正确性。

**启动时删除看似保留的路径。** 崩溃后仅凭文件名无法证明事务所有权；安全自动恢复需要持久记录。

**浏览器侧解压和写入。** 浏览器校验不能建立宿主文件系统权限，还会绕过由提供器拥有的发现生命周期。

## 验证

包测试固定压缩包和图片校验、资源上限、严格清单解析、确定性清单、分键并发、回滚、清理和仅受管卸载。Remote 与文件系统提供器测试固定结构化结果和提交后失效。客户端 store、组件、locale、slot、过期响应和浏览器组合覆盖固定通过生成式 API 实现的本地化工作流。

## 后果

该设计为浏览器提供稳定的类型化工作流，同时把不可信输入和破坏性权限留在宿主。手工管理技能会以关闭方式失败，发现过程只能观察到完整提交的目标。

Base64 会复制有界压缩包数据，进程内锁不能协调多个宿主进程，崩溃可能留下保留命名的同级残留。流式传输、跨进程协调和持久崩溃恢复可以在不改变清单所有权与发布语义的前提下演进。

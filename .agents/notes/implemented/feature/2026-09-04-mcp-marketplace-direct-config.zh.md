# Agent Note: 市场中的 MCP 直连服务配置

状态：已实现

[English](2026-09-04-mcp-marketplace-direct-config.md) | 中文

## 问题

市场 MCP 标签页此前只接受签名 ZIP 包。接入一个远端 MCP 端点——或一个本地 stdio 服务——需要走完整的发布者工具链：构建归档、计算文件表哈希、用 Ed25519 签名再上传。对于用户自己背书的服务，打包仪式不带来任何安全性，只挡住了最常见的路径。

## 决策

MCP 标签页在包上传旁新增直连配置面板：跨两种传输创建、编辑和删除用户声明的服务。市场服务拥有一个仅引用的存储（`installRoot` 下的 `.mcp-direct-configs.json`），网关在保存时热挂载、删除时卸载，走与包路径相同的 `McpClientManager` 挂载——直连变更不绑定重启。

适用的安全规则原样迁移：凭据槽保持空固定值规则，stdio 命令必须在 `stdioInterpreters` 白名单内，每次 stdio 保存都需要与包安装相同的 `confirmLocalExecution` 披露。不迁移的是文件表：直连条目没有签名载荷，参数可以指向用户磁盘上的绝对路径，`cwd` 由用户声明且保存时校验存在——替代受管包目录。用户以 cordis.yml 条目的方式直接背书该条目；披露弹窗在保存路径上说明这一点，而非只在安装时。

服务名在直连条目与受管包之间双向唯一，检查在市场服务的 keyed mutex 内完成。同名编辑先释放命名空间再重新挂载（管理器拒绝并发重名保留）；改名则先挂新名再释放旧名，因此挂载失败时旧服务仍在运行、记录不变、条目以诊断标记为降级。

## 已否决的备选方案

- **浏览器生成未签名包**：零后端改动，但结果仍是包——清单噪音、重启语义，以及一个暗示存在实际上不存在的证明的签名弹窗。
- **仅支持直连 HTTP**：成本更低，但把表面割裂了——本地服务即便出自用户之手，也仍被挡在发布者工具链后面。
- **写 mcp-client 的 cordis.yml 配置**：声明式配置属于加载期，不可运行时变更；热加载需要文件监听语义，且终究要重启。

## 后果

直连配置是高级用户路径，风险画像与之匹配：确认门覆盖子进程决策，但执行的代码就是用户指定的内容。包安装与直连保存共享一个命名空间，包不会静默遮蔽直连条目，反之亦然。解析后的凭据值仍只在挂载调用内存在；直连条目只持久化引用名。重启绑定模型仍治理包——只有直连配置是即时的。
